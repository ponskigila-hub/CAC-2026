# Methodology

The target is title-derived career family, not hiring success. See README for task framing, model comparison and limitations. The deterministic label and skill rules are in `src/core.py`. Identical role-skill pairs are deduplicated; identical skill vectors are grouped across the local pool. Exact normalized text is deduplicated within each source and role; nonidentical near duplicates are not guaranteed absent. The international pool excludes any skill vector identical to a local vector. No metadata features (job title, source, location, education or salary) enter the classifier.

A fixed grouped holdout is set aside. Four-fold grouped cross-validation within development chooses hyperparameters, then the best base classifier and hybrid weight based on pooled macro F1. The international model uses the same chosen base estimator, fit on local development plus filtered external profiles. Default is selected from grouped CV, not the holdout. All final estimators fit development; local development defines demand profiles. Majority baseline and overlap baseline provide comparisons. Bootstrap uses groups instead of rows, 100 replicates. Source-held-out results use the chosen hybrid configuration without retuning; this is a retrospective sensitivity check, not a fresh independent external validation. Macro F1 on source subsets uses observed/predicted class union; tiny or missing classes limit comparisons.

Specializations are separately inferred from within-family title rules and require at least ten development profiles. They are descriptive coverage rankings and not evaluated classifiers. The co-occurrence baseline selects the policy with maximum oracle-field masked-skill recovery on development folds; final test masks one skill per eligible profile and selects field from the remaining skills. It compares a global-frequency baseline, field-frequency end-to-end and conditional co-occurrence end-to-end, and an oracle-field diagnostic. Candidate skills are limited to the 25 most frequent per field. Known-skill conditional support requires at least 3 development mentions. No actual applicant labels or learning outcome data are available.

Additional evaluation: `src.quality` menghitung kemiripan Jaccard test terhadap development; `src.gap_rank` memilih kebijakan ranking berbasis skill tersisa menggunakan grouped CV. Metode sebelumnya tetap tersimpan sebagai pembanding. Lihat README untuk hasil dan keterbatasan.

## Final skill ranking and class imbalance

The deployed learning ranking uses squared-Jaccard neighborhood similarity, selected from five policies by end-to-end grouped development CV (`src/gap_rank.py`). The co-occurrence approach remains a baseline. Candidate skills have positive development support; coverage simulation retains its top-25 profile definition.

`src/balance.py` compares ten scenarios using the same local grouped split. Augmentation excludes Software Development, exact overlapping profiles and conflicting external labels. Weighting and resampling occur within training folds. The default Hybrid maximizes development Macro F1; moderate inverse-frequency square-root weighting is an optional alternative. Demand weights remain based on local development. All reused-holdout comparisons are retrospective.
